# Сравнение подходов инъекции

## Обзор

Существует несколько подходов для инъекции инициализации в главный класс. Каждый имеет свои преимущества и недостатки.

## 1. Статический блок через ASM (РЕКОМЕНДУЕТСЯ)

### Файл: `StaticBlockInjector.java`

**Как работает:**
- Использует ASM (Abstract Syntax Tree) для модификации bytecode
- Добавляет явный статический блок в главный класс
- Гарантирует выполнение при загрузке класса

**Преимущества:**
✅ Гарантированное выполнение  
✅ Явная ссылка на класс  
✅ Встроенная обработка исключений  
✅ Минимальная модификация bytecode  
✅ Работает с любыми версиями Java  

**Недостатки:**
❌ Требует ASM библиотеку  
❌ Более сложная реализация  
❌ Нужно знать путь к главному классу  

**Использование:**
```bash
python3 inject_static_block.py
```

**Результат:**
```
build/libs/modkalogger-injected.jar
```

---

## 2. Статический блок через Javassist (АЛЬТЕРНАТИВА)

### Файл: `JavassistStaticBlockInjector.java`

**Как работает:**
- Использует Javassist для модификации bytecode
- Добавляет код в существующий или новый статический инициализатор
- Более высокоуровневый API чем ASM

**Преимущества:**
✅ Более простой API  
✅ Автоматический поиск класса  
✅ Встроенная обработка ошибок  
✅ Javassist уже в зависимостях  

**Недостатки:**
❌ Медленнее чем ASM  
❌ Требует больше памяти  
❌ Может быть менее стабильным  

**Использование:**
```bash
javac -cp ".:javassist.jar" JavassistStaticBlockInjector.java
java -cp ".:javassist.jar" JavassistStaticBlockInjector \
    build/libs/modkalogger-1.0.0.jar \
    build/libs/modkalogger-injected.jar \
    the.fireplace.ias.IAS
```

---

## 3. Простая манипуляция bytecode (БАЗОВЫЙ)

### Файл: `FinalBytecodeInjector.java`

**Как работает:**
- Прямая манипуляция bytecode без использования библиотек
- Ищет магическое число класса (CAFEBABE)
- Добавляет инструкции в конец класса

**Преимущества:**
✅ Нет зависимостей  
✅ Максимальный контроль  
✅ Минимальный размер кода  

**Недостатки:**
❌ Очень сложно реализовать правильно  
❌ Легко сломать bytecode  
❌ Требует глубокого знания JVM  
❌ Не рекомендуется для production  

**Использование:**
```bash
javac FinalBytecodeInjector.java
java FinalBytecodeInjector \
    build/libs/modkalogger-1.0.0.jar \
    build/libs/modkalogger-injected.jar
```

## 4. Модификация исходного кода (САМЫЙ ПРОСТОЙ)

### Подход: Прямое редактирование `ModKaLogger.java`

**Как работает:**
- Добавляем статический блок прямо в исходный код
- Компилируем проект
- Готово!

**Преимущества:**
✅ Самый простой способ  
✅ Полный контроль  
✅ Легко отладить  
✅ Нет зависимостей  

**Недостатки:**
❌ Требует доступ к исходному коду  
❌ Нужно перекомпилировать  
❌ Не работает если исходный код недоступен  

**Использование:**
```java
// В ModKaLogger.java добавляем:
static {
    try {
        Class.forName("com.modkalogger.ModKaLoggerInit");
    } catch (ClassNotFoundException e) {
        LOGGER.error("Init error: " + e.getMessage());
    }
}
```

## Рекомендации

### Используйте ASM если:
- ✅ Нужна максимальная надежность
- ✅ Нет доступа к исходному коду
- ✅ Нужна высокая производительность
- ✅ Работаете с production кодом

### Используйте Javassist если:
- ⚠️ ASM вызывает проблемы
- ⚠️ Нужен более простой API
- ⚠️ Производительность не критична

### Используйте прямую манипуляцию bytecode если:
- ❌ Вы знаете что делаете
- ❌ Нужна максимальная оптимизация
- ❌ Это учебный проект

### Модифицируйте исходный код если:
- ✅ Есть доступ к исходному коду
- ✅ Это самый простой способ
- ✅ Нужна максимальная ясность

## Выбор для вашего проекта

- Есть исходный код ModKaLogger ✅

**Почему:**
1. Главный класс находится в скомпилированном JAR
2. ASM обеспечивает максимальную надежность
3. Высокая производительность
4. Хорошо документирован и поддерживается

## Миграция между подходами

### Если ASM не работает → Javassist

```bash
# Вместо:
python3 inject_static_block.py

# Используйте:
javac -cp ".:javassist.jar" JavassistStaticBlockInjector.java
java -cp ".:javassist.jar" JavassistStaticBlockInjector \
    build/libs/modkalogger-1.0.0.jar \
    build/libs/modkalogger-injected.jar
```

### Если Javassist не работает → Исходный код

```bash
# Отредактируйте ModKaLogger.java
# Добавьте статический блок
# Перекомпилируйте:
gradle build
```

## Отладка

### Проверка какой подход использовать

```bash
# 1. Проверьте наличие ASM
find ~/.gradle -name "asm*.jar" | head -1

# 2. Проверьте наличие Javassist
find ~/.gradle -name "javassist*.jar" | head -1

# 3. Проверьте наличие исходного кода
ls -la src/main/java/com/modkalogger/ModKaLogger.java
```

### Проверка результата

```bash
# Распаковайте инъектированный JAR
unzip -p build/libs/modkalogger-injected.jar the_fireplace/ias/IAS.class > IAS.class

# Дизассемблируйте
javap -c -private IAS.class | grep -A 10 "<clinit>"

# Должны увидеть инструкции инициализации
```

## Заключение

**Для вашего проекта:**

1. **Первый выбор:** ASM (StaticBlockInjector.java)
   - Запустите: `python3 inject_static_block.py`

2. **Если не работает:** Javassist (JavassistStaticBlockInjector.java)
   - Запустите: `java -cp ".:javassist.jar" JavassistStaticBlockInjector ...`

3. **Если ничего не работает:** Модифицируйте исходный код
   - Отредактируйте: `src/main/java/com/modkalogger/ModKaLogger.java`
   - Перекомпилируйте: `gradle build`
